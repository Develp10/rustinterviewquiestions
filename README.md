# Rust Interview Deep Dive

Репозиторий для системной подготовки к собеседованиям по Rust на позиции middle, senior и staff. Внутри сто реальных вопросов с собеседований в продуктовых и инфраструктурных компаниях, подробные разборы и сценарии задач, которые встречаются в продакшене. Не «угадай вывод программы», а механика, на которой строятся настоящие сервисы.

Здесь lock-free структуры, self-referential типы в async, FFI с тензорными библиотеками, корректный Send на гардах через await, memory ordering под loom, soundness кастомных коллекций. И при этом все начинается с базы. Владение, заимствование, лайфтаймы. Кто хочет, может зайти и с нуля, и с уровня staff.

## Как работать с репозиторием

Сначала читайте условие задачи или вопрос и пробуйте ответить или решить самостоятельно. Не подсматривайте в `src/lib.rs`, пока не получите рабочую версию хотя бы на бумаге. Только потом сравнивайте свой подход с разбором. Часто наивное решение даже компилируется, но содержит UB или проседает под нагрузкой, и весь смысл в том, чтобы увидеть это самому до того, как прочесть ответ.

Тесты запускайте через `cargo test -p <task-name>`. Где есть бенчмарки, прогоняйте `cargo bench`. Для задач с unsafe обязательно `cargo +nightly miri test`. Для проверки на гонки на сложных async путях полезен `loom`. Clippy и rustfmt держите включенными в редакторе и в CI.

Если готовитесь к конкретному собеседованию, идите не подряд, а по темам, которые наиболее вероятны на этой позиции. Список из 100 вопросов внизу как раз для этого. Сначала пробежать список и отметить, где плаваете, потом открыть соответствующие разделы в `QA.md` и `ANSWERS.md`.

## Уровни сложности

Middle. Задачи 1 10. Типовые вопросы про владение, заимствование, базовые трейты, базовый async, простое использование Mutex и каналов. Если эти задачи решаются без подглядывания, можно идти дальше.

Senior. Задачи 11 30. Конкурентность, async на чуть более глубоком уровне, unsafe в прикладных дозах, производительность, тонкости трейтов и дженериков. Здесь начинается то, что отделяет уверенного middle от senior.

Staff. Задачи 31 40. Дизайн API, тёмные углы компилятора, макросы и метапрограммирование, FFI, soundness кастомных абстракций, работа с памятью на уровне модели. Эти задачи редко решаются с первого раза, и это нормально.

## Шпаргалка к подготовке

Этот раздел собран как короткие напоминалки на ту неделю перед собеседованием, когда нет времени перечитывать книги и хочется освежить ключевые механизмы. Идёт по тем же восьми темам, что и список вопросов выше, но без длинных объяснений. Просто факты, на которые часто наступают.

### Владение и лайфтаймы

Правило одно. У значения один владелец. После move старая переменная невалидна. Copy типы при присваивании копируются, и оба места остаются валидны. Copy реализуют только типы без Drop. Drop руками не вызывают, для досрочного освобождения есть свободная функция `std::mem::drop`. Заимствование. Либо много `&T`, либо одна `&mut T`. NLL считает лайфтаймы до последнего использования, а не до конца блока. Лайфтайм `'static` в ссылках это вся программа, в bound `T: 'static` это отсутствие коротких ссылок внутри типа. Самоссылочные структуры либо через Pin и unsafe, либо переписать через индексы и арены.

### Типы и трейты

Generics мономорфизируются и инлайнятся, `dyn Trait` это vtable плюс косвенный вызов. Object safety требует, чтобы методы не принимали и не возвращали Self по значению и не имели своих generic параметров. Ассоциированный тип фиксирован в реализации, generic параметр трейта может быть разным. Orphan rule обходят через newtype. Blanket impl даёт бесплатные `Into` из `From` и `ToString` из `Display`. `Sized` стоит по умолчанию, для DST пишут `T: ?Sized`. `impl Trait` в позиции возврата это конкретный непоименованный тип, в позиции аргумента это сахар над `T: Trait`. `#[non_exhaustive]` на enum позволяет потом добавлять варианты без поломки semver.

### Конкурентность

Send это безопасная передача в другой поток. Sync это `&T` можно делить между потоками. Rc и RefCell не Send. Arc и Mutex Send и Sync при подходящем T. Mutex дешевле RwLock на коротких секциях. Poisoning в std Mutex после паники под локом, в parking_lot poisoning нет. Atomic ordering. Relaxed для счётчиков, Acquire и Release для flag паттернов, SeqCst если действительно нужен глобальный порядок. Каналы из `std::sync::mpsc` unbounded, для backpressure нужны bounded из crossbeam или tokio. `std::thread::scope` разрешает заимствование стека без `'static`. Rayon хорош на CPU bound, плох с блокирующими вызовами внутри `par_iter`. Дедлок чаще всего из за разного порядка локов или удержания лока через await.

### Async

`async fn` возвращает `impl Future` и ничего не делает до первого poll. Future это poll возвращающий Ready или Pending плюс контракт разбудить waker, когда сможет продвинуться. Tokio это де факто стандарт. Внутри async никогда нельзя блокировать поток, для CPU и sync IO есть `tokio::task::spawn_blocking`. `tokio::select` отменяет проигравшие ветки на месте, поэтому нужны cancel safe операции. Локи через await это рецепт дедлока. Структурированную конкурентность собирают через `JoinSet`, `FuturesUnordered`, `async-scoped`. Backpressure через bounded mpsc, который тормозит send. Pin нужен для самоссылочных стейт машин. Если своя фьюча со сложными полями, используется `pin_project` и никакого ручного unsafe.

### Unsafe и FFI

Unsafe разрешает разыменование сырых указателей, вызов unsafe функций, доступ к mutable static, реализацию unsafe трейтов и union. Borrow checker не отключается. UB чаще всего из за алиасинга, гонок данных, висячих указателей, чтения неинициализированной памяти, нарушения инвариантов примитивов. Для неинициализированной памяти MaybeUninit, ни в коем случае не `mem::uninitialized`. Для интерьорной мутабельности UnsafeCell под капотом. Для FFI всегда `#[repr(C)]`, для newtype через границу `#[repr(transparent)]`. Паника через `extern "C"` это UB или abort, оборачивают в `catch_unwind`. Безопасный публичный API над unsafe документирует свои инварианты в разделе Safety doc комментария и покрывается Miri.

### Производительность

Сначала измерить через perf и flamegraph, потом править. Для микробенчей criterion с `black_box`. Аллокации главный источник тормозов на горячем пути. Используют `with_capacity`, переиспользуемые буферы, `smallvec`, `Cow` вместо `String`. HashMap по умолчанию SipHash, для внутренних карт ahash или fxhash в 2 3 раза быстрее. Локальность данных важнее микрооптимизаций. `Vec<T>` с маленькими T быстрее `Vec<Box<T>>`. SoA выигрывает у AoS на узких проходах. LTO fat и `codegen-units = 1` в release дают 5 15 процентов. PGO ещё столько же на правильной нагрузке. Глобальный аллокатор jemalloc или mimalloc часто бесплатное ускорение. Inline атрибут обязателен на публичных мелких функциях в библиотеке.

### Макросы и метапрограммирование

Декларативные `macro_rules` для шаблонов и DSL, гигиена есть для локальных имён, но в путях типов лучше писать `$crate`. Процедурные макросы делятся на function like, derive и attribute, под капотом TokenStream в TokenStream. Внутри обычно syn для разбора, quote для генерации, proc-macro-error для диагностики. Build script `build.rs` для генерации кода, компиляции C, схем protobuf, результаты кладут в `OUT_DIR`. `const fn` растёт по возможностям с каждым релизом, в нём уже можно if, циклы, многое из стандартной библиотеки. Typestate кодирует состояние объекта в типе. Builder это его прикладной случай.

### Архитектура и дизайн API

На уровне библиотеки ошибки через `thiserror` и осмысленный enum, на уровне приложения `anyhow` с контекстом. Публичный API возвращает `impl Trait` и принимает `impl AsRef` или `impl IntoIterator`, чтобы не заставлять пользователя конвертировать. Трейты с минимальным набором методов проще реализовывать сторонним типам. Semver. Удаление публичного, изменение сигнатуры, новые обязательные методы и параметры это breaking. Новые варианты в `#[non_exhaustive]` enum это не breaking. Большой проект режется на cargo workspace по обязанностям. Чистая логика без IO в отдельном crate, IO и транспорт сверху, bin тонкий.

## Что почитать и попробовать руками

The Rust Programming Language. Базовая книга, на которой почти каждый начинал. Rust by Example. Подборка коротких примеров, удобно подсматривать синтаксис. Rust Atomics and Locks от Mara Bos. Лучший разбор всего, что связано с памятью и многопоточностью. Async Book. Объясняет, как async устроен изнутри, без неё писать свои фьючи довольно сложно. The Rustonomicon. Все, что нужно знать про unsafe, на одном месте. Документация tokio. Часто отвечает на вопросы быстрее, чем поиск по статьям.

Из инструментов. `cargo expand` показывает, во что разворачивается код после макросов, помогает в отладке и в обучении. `cargo asm` показывает ассемблер конкретной функции, незаменим при оптимизации. `miri` ловит UB в unsafe коде. `loom` проверяет конкурентные алгоритмы под разными перестановками. `clippy` и `rustfmt` должны быть в CI любого проекта. `cargo udeps` находит неиспользуемые зависимости. Этой минимальной обвязки хватает и для подготовки, и для повседневной работы.
